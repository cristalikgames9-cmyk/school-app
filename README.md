# Онлайн-школа — 1 класс (v3, уроки — отдельными файлами)

Эта версия хранит уроки так, как тебе удобно: `data/lessons/<предмет>/*.txt`,
каждый файл — один урок целиком, включая задания внутри. Отдельного
`homeworks.json` больше нет — он не нужен.

## Структура данных

```
data/
  subjects.json          — список предметов (не менялся)
  lessons/
    math/
      math-1.txt           — урок + его задания одним файлом
    russian/
      russian-1.txt
    lit/
      reading-1.txt
    world/
      world-1.txt
    izo/                    — пока пусто (папка есть, уроков нет)
    training/                — пока пусто
```

Название папки — просто для порядка на диске, реальная привязка урока к
предмету идёт по полю `"subjectId"` внутри самого файла.

⚠️ **Главное правило: `"id"` урока должен быть уникальным на весь сайт**, а
не только внутри предмета — потому что страница `/lesson.html?id=...` не
знает, из какой он папки, и ищет по всем сразу. Если два урока в разных
предметах случайно получат одинаковый `id` — откроется первый найденный, не
тот что нужен. Сервер это отследит и **напишет предупреждение в консоль**
(не упадёт), но лучше не допускать: называй id с префиксом предмета —
`math-1`, `math-2`, `russian-1` и т.д.

Если хочешь, чтобы уроки внутри предмета шли по порядку — называй сами
**файлы** с номерами: `01-chisla.txt`, `02-figury.txt` (сервер читает файлы
в алфавитном порядке).

## Формат одного файла урока

```json
{
  "id": "math-2",
  "subjectId": "math",
  "title": "Урок 2. Число и цифра 2",
  "scheduledAt": "2026-09-02T09:00",
  "videoUrl": "https://kinescope.io/embed/AbCdEfGhIjKlMnOp12",
  "content": "Текст-описание урока, который увидит ученик под видео.",
  "tasks": [
    {
      "id": "t1",
      "type": "normal",
      "question": "Сколько будет 1 + 1?",
      "image": null,
      "options": [
        { "id": "A", "text": "1" },
        { "id": "B", "text": "2" },
        { "id": "C", "text": "3" }
      ],
      "correctAnswer": "B"
    },
    {
      "id": "t2",
      "type": "multiple",
      "question": "Отметь ВСЕ картинки, где предметов ровно два.",
      "image": null,
      "options": [
        { "id": "A", "text": "2 яблока" },
        { "id": "B", "text": "1 груша" },
        { "id": "C", "text": "2 мяча" }
      ],
      "correctAnswer": ["A", "C"]
    },
    {
      "id": "t3",
      "type": "text",
      "question": "Напиши число, которое идёт после 1.",
      "image": null,
      "correctAnswer": "2"
    }
  ]
}
```

**`videoUrl`** — это уже готовая embed-ссылка, вставляется в `<iframe>` как
есть, ничего собирать не нужно. Для Kinescope: в кабинете открой видео →
«Поделиться» / «Embed» → скопируй ссылку вида
`https://kinescope.io/embed/AbCdEfGhIjKlMnOp12` целиком.

**Типы задач (`type`):**
- `"normal"` — один правильный вариант. `correctAnswer` — id варианта, например `"B"`.
- `"multiple"` — несколько правильных вариантов (чекбоксы). `correctAnswer` —
  массив id, например `["A", "C"]`. Если ученик отметит только часть верных —
  засчитается «частично верно».
- `"text"` — свободный ответ (поле ввода вместо вариантов). `correctAnswer` —
  строка (сравнение без учёта регистра и лишних пробелов), либо массив строк,
  если подходит несколько формулировок: `"correctAnswer": ["2", "два"]`.

**`image`** — необязательное поле, ссылка на картинку к вопросу (или `null`).

## Календарь уроков

На главной странице под предметами находится календарь на семь дней. При
открытии он показывает текущую неделю, стрелки переключают недели, а кнопка
«Сегодня» возвращает к актуальной неделе.

Чтобы добавить урок в календарь, вставь в файл урока одну строку после
`"title"`:

```json
"scheduledAt": "2026-09-02T09:00",
```

Формат всегда такой: `ГГГГ-ММ-ДДTЧЧ:ММ`. В примере урок назначен на
2 сентября 2026 года в 09:00. Часы записываются от `00:00` до `23:59`.
Поле `scheduledAt` можно не указывать — тогда сам урок продолжит работать,
но в календаре показан не будет. У каждого урока может быть одна дата и
одно время; карточка в календаре ведёт прямо на страницу урока.

После добавления/правки файла урока — просто обнови страницу в браузере,
сервер перечитывает файлы (с кэшем на 3 секунды, поэтому изменения видно
почти сразу, перезапускать `npm start` не обязательно).

## Что нужно сделать в Supabase (обязательно)

Код использует существующие таблицы `users` и `homework_results` (не
`answers`). Перед развёртыванием этой версии открой Supabase → SQL Editor и
целиком выполни файл:

`supabase/migrations/20260811_progress_mailerlite.sql`

Миграция добавляет данные ученика и родителя, поля месячного отчёта,
`created_at` для ответов, а также уникальный индекс, запрещающий менять уже
зафиксированный ответ. Она не удаляет существующие записи.

Сервер должен использовать `service_role` key. Не помещай этот ключ в
браузерный JavaScript и не коммить `.env`.

## Настройка `.env`

Скопируй `.env.example` в `.env` и заполни секреты только в настройках
хостинга. Сам `.env` исключён из Git.

Если `.env` когда-либо был опубликован в репозитории, старые
`SUPABASE_KEY` и `COOKIE_SECRET` нужно заменить. Удаление файла из нового
коммита не удаляет секрет из старой истории Git.

## Месячная статистика

Отчёт считается за календарный месяц в часовом поясе `REPORT_TIME_ZONE`, а
не за 30 дней с момента регистрации. По умолчанию используется
`America/Costa_Rica`.

- правильный ответ: 1 балл;
- частичный ответ: 0,5 балла;
- неверный ответ: 0 баллов;
- оценка: `(верные + 0,5 × частичные) / все ответы месяца × 100`.

Урок считается завершённым в том месяце, когда был дан последний
необходимый ответ этого урока. Поэтому урок может начаться в июле, а
завершиться и попасть в отчёт августа.

## MailerLite

MailerLite различает группы (их часто называют тегами) и пользовательские
поля. Числа и имя передаются именно в пользовательские поля; группы нужны
только для включения подписчика в нужную рассылку.

Синхронизируются в созданные поля MailerLite:

- имя ученика → `name`;
- завершённые уроки → `lessons_completed`;
- решённые задачи → `tasks_answered`;
- верные ответы → `correct_count`;
- частичные ответы → `partial_count`;
- неверные ответы → `incorrect_count`;
- оценка 0–100 → `score_period`.

Все числовые значения относятся к текущему календарному месяцу. Отдельное
поле месяца пока не отправляется, потому что в MailerLite оно не создано.

Точные ключи полей задаются переменными `MAILERLITE_FIELD_*` из
`.env.example`, а ID групп — через `MAILERLITE_GROUP_IDS` (через запятую).
Для совместимости код также понимает старые имена `MAILERLITE_API_KEY` и
`MAILERLITE_GROUP_ID` из ветки `local-mailerlite`. Токен хранится только на
сервере. Если токен не
задан, сайт продолжает работать и обновляет те же показатели в таблице
`users`, чтобы существующая автоматизация Supabase → MailerLite могла их
синхронизировать.

Подписчик создаётся и обновляется только если родитель явно отметил
согласие при регистрации.

Колонка `newsletter_subscribed` из первой локальной версии сохраняется и
обновляется вместе с новым полем согласия, чтобы прежняя интеграция не
перестала работать после миграции.

## Что было починено при переходе на файловую схему

- Загрузчик уроков теперь ищет по всем папкам `data/lessons/*/`, а не читает
  один общий `lessons.json`.
- Роуты `/api/subjects/:id`, `/api/lessons/:id`, `/api/homework/:lessonId`
  переписаны под новый источник данных.
- Проверка ответов в ДЗ переписана под новую схему: `correctAnswer` — id
  варианта (буква), а не индекс, плюс добавлена поддержка типа `"text"`
  (свободный ответ) и `"multiple"` (частичный зачёт).
- Прогресс на главной странице считает урок пройденным, если отвечены все
  его `tasks` (столько же записей в Supabase, сколько задач в файле урока).
- Твои 4 существующих урока (математика, чтение, русский, окружающий мир) —
  автоматически перенесены из старой схемы в новую, ничего не потерялось.
  Видео пока не привязано (`"videoUrl": "PASTE_EMBED_URL_HERE"`) — вставь
  свои ссылки.
- Проверка на задвоенные `id` урока — предупреждение в консоли сервера, а не
  тихая поломка.
