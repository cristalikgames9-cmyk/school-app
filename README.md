## Что было сломано и что я поправил

1. **`.env` не был в `.gitignore`** — добавил, иначе ключи Supabase ушли бы в
   публичный GitHub-репозиторий.
2. **Не было `package.json`** — создал, со всеми нужными зависимостями
   (`express`, `dotenv`, `cookie-parser`, `@supabase/supabase-js`, `bcryptjs`).
3. **Пароли не хешировались при регистрации** и сравнивались как обычный
   текст при входе — при этом в базе уже лежат bcrypt-хеши. Теперь
   регистрация хеширует пароль через `bcryptjs`, вход сравнивает через
   `bcrypt.compare` — работает и со старыми, и с новыми пользователями.
4. **Кука сессии не была подписана** — раньше значение `userId` в куке можно
   было подделать вручную (`document.cookie = "userId=1"`) и зайти в чужой
   аккаунт без пароля. Теперь кука подписывается секретом (`COOKIE_SECRET` в
   `.env`) через `cookie-parser`.
5. **`data/lessons.json` был в старом формате** (уроки вложены по предмету),
   а весь остальной код уже ждал плоский массив с полем `subjectId` у
   каждого урока. Пересобрал файл в нужном формате.
6. **Не было роутов** `GET /api/lessons/:id` и `GET/POST /api/homework/...`
   — фронтенд их вызывал, но сервер ничего не отдавал. Добавил оба, плюс
   `POST /api/auth/logout`.
7. **Проверка ответов в ДЗ была битая**: код сверял `task.answer`, которого
   не существует — в `homeworks.json` поле называется `correct` и хранит
   **индексы** правильных вариантов. Переписал логику проверки на индексы,
   плюс вопросы с одним правильным ответом (`type: "single"`) теперь
   показывают радиокнопки вместо чекбоксов (иначе можно было выбрать
   несколько при одном верном).
8. **`lesson.js` не выводил видео и кнопку ДЗ** — доделал: подставляет
   Kinescope-плеер и ссылку на домашку.
9. **Прогресс-бар на главной был в вёрстке, но не заполнялся** — теперь
   `/api/auth/me` считает прогресс (сколько уроков пройдено полностью, то
   есть отвечены все задачи урока), а `index.js` рисует полосу и текст.
10. Добавил кнопку **«Выйти»** на главной — CSS для неё уже был в файле, но
    сама кнопка потерялась при переделке.
11. Отметки пройденных уроков (зелёная рамка + ✅) на странице предмета —
    CSS `.lesson-card.completed` уже был готов, просто не использовался.

## Что нужно сделать в Supabase (обязательно, иначе регистрация/вход не заработают)

Зайди в свой проект на supabase.com → **SQL Editor** → вставь и выполни:

```sql
-- Таблица users у тебя, судя по всему, уже есть (там уже есть bcrypt-хеши).
-- Если вдруг её нет — создай так:
create table if not exists users (
  id bigint generated always as identity primary key,
  username text unique not null,
  password text not null, -- bcrypt-хеш, не сам пароль
  created_at timestamptz default now()
);

-- Новая таблица — сюда пишутся ответы на домашние задания
create table if not exists answers (
  id bigint generated always as identity primary key,
  user_id bigint not null references users(id) on delete cascade,
  lesson_id text not null,
  question_id text not null,
  status text not null, -- correct | partial | incorrect
  selected_options jsonb not null default '[]'::jsonb,
  created_at timestamptz default now(),
  unique (user_id, lesson_id, question_id)
);

-- Проект небольшой, для узкого круга, своя система входа (не Supabase Auth) —
-- поэтому проще отключить Row Level Security, иначе Supabase будет
-- блокировать вставку/чтение по умолчанию:
alter table users disable row level security;
alter table answers disable row level security;
```

⚠️ Если у твоей таблицы `users` поле `id` не `bigint`, а, например, `uuid` —
поменяй `user_id bigint` на `user_id uuid` в SQL выше.

## Настройка `.env`

В `.env` уже есть `SUPABASE_URL` и `SUPABASE_KEY`. Добавь ещё одну строку —
секрет для подписи кук (придумай любую длинную случайную строку):

```
COOKIE_SECRET=любая-длинная-случайная-строка-придумай-сам
PORT=3000
```

Ключ `SUPABASE_KEY` у тебя сейчас — «publishable» (аналог старого anon-ключа).
Это нормально для этого проекта, так как RLS отключена по SQL выше. Если
хочешь надёжнее — можно взять `service_role` ключ в Supabase (Project
Settings → API) и подставить в `SUPABASE_KEY`: он используется только на
сервере (в `.env`), в браузер никогда не попадает, и работает даже если RLS
включена.

варианты A/B/C/D) — она не совпадает со схемой, которая реально работает

черновику.

## Как добавить новый урок

**`data/lessons.json`** — допиши объект в массив:
```json
{
  "id": "izo-1",
  "subjectId": "izo",
  "title": "Урок 1. Цвета радуги",
  "content": "Учимся смешивать цвета.",
  "videoId": "ID_ИЗ_KINESCOPE"
}
```
`videoId` — часть ссылки Kinescope после `/embed/` (в кабинете Kinescope:
«Поделиться» → скопировать ссылку вида `https://kinescope.io/embed/AbC123`,
нужен кусок `AbC123`).

**`data/homeworks.json`** — добавь ключ с тем же `id`, что у урока, и 7 задач:
```json
"izo-1": [
  {
    "id": "q1",
    "question": "Какой цвет получится, если смешать синий и жёлтый?",
    "type": "single",
    "options": ["Зелёный", "Оранжевый", "Фиолетовый"],
    "correct": [0]
  }
]
```
`type: "single"` — один верный ответ (`correct` с одним индексом),
`type: "multiple"` — несколько верных (`correct` с несколькими индексами,
частичное совпадение засчитается как «частично верно»). Картинку к вопросу
можно добавить полем `"image": "https://..."` — ссылка на файл картинки.

После правки — `Ctrl+C` и заново `npm start`.
